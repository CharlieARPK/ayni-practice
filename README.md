# Ayni — ひとりで、掛け合う。

スマートフォン向け、無料で使える楽器の掛け合い練習PWAです。ブラウザーだけで音声生成・曲保存・オフライン利用ができます。アカウント、バックエンド、有料API、外部CDNは不要です。

[アプリを開く](https://charliearpk.github.io/ayni-practice/) · [公開リポジトリ](https://github.com/CharlieARPK/ayni-practice)

## 起動

Node.js 20.11以降で、依存パッケージのインストールなしで起動できます。

```sh
npm run dev
```

http://localhost:5173 を開きます。開発用HTTPサーバーはローカルプレビュー専用で、本番運用には不要です。

```sh
npm test
```

## 静的公開とスマートフォンでの利用

GitHub Pagesで公開できます。既存のGitHubアカウントだけで利用でき、GitHub Freeでは公開リポジトリを使います。`.github/workflows/pages.yml` がテスト・公開ファイルの生成・公開を行います。公開対象はアプリとデモ曲のみで、読み込んだ曲や編集内容は端末内に保存します。

`npm run package` で公開用の `dist/` を作成できます。Windowsでは `ayni-public.zip` も作成します。アプリに必要なファイルだけを含み、テスト記録や利用者の楽曲JSONは含めません。ZIPの直下にindex.htmlがある構成です。作り直すと生成済みdistを置き換えます。

`dist/` またはZIPをHTTPS対応の静的ホスティングに配置してください。実行用サーバーもビルドも不要です。サブディレクトリへの配置にも対応しています。PCの電源が切れていても公開URLを開けます。

初めて公開する場合の手順と、保存した曲の移行方法は [公開手順](./DEPLOY.md) に記載しています。

1. AndroidのChromeでHTTPSのURLを開きます。
2. 「オフライン対応」の表示を確認します。
3. Chromeのメニューから「ホーム画面に追加」（インストール）を選びます。
4. JSONを追加し、曲とパートを選択します。
5. 自分が吹く側、小節区間、BPMを設定して再生します。

Service WorkerはHTTPSまたはlocalhostが必要です。スマートフォンからPCのLAN IPをHTTPで開いた場合、オフライン・インストール機能は使えません。`file://` での直接起動にも対応していません。

## 機能

- 「デモを選ぶ」から3つの練習を準備できます。手元の楽譜・JSONファイルは不要です。
- 音名で読む簡易楽譜にドレミ、実音、担当、音価、移動記号を表示。4小節ずつ閲覧でき、再生中は現在小節へ追従します。
- 「演奏の道順」で展開後の小節順と現在位置を確認。D.S.前後でTo Codaの動作が変わる様子も見られます。

- 任意のパート名、複数曲・複数パート、JSON検証、localStorageへの保存・削除。
- 前だけ／後だけ／両方の再生。自分が吹く側に合わせて相手側を選択。
- BPM 30〜240、数値入力、＋−、スライダー、標準テンポへの復帰。
- 開始・終了小節指定、一覧から選択、現在小節・拍の表示。
- 現在小節／開始小節から即座にもう一度、演奏順で1小節戻る。
- 区間ループ、0/1/2小節カウントイン、メトロノーム。
- 区間練習と楽譜どおりの演奏。反復、括弧、D.C./D.S./Segno/Coda/To Coda/Fine、途中の拍子変更。
- オフラインPWA。ネットワークなしでサンプル・保存済み曲・ローカルJSON取り込み・ヘルプが動作。
- 画面表示中のWake Lockを可能な環境で取得。バックグラウンド移行・音声中断時は、安全に停止して位置を保持。

## 設計

| ファイル | 責務 |
| --- | --- |
| `src/schema.js` | 正式JSON Schemaと、その使用キーワードの検証処理 |
| `src/format.js` | 旧JSONの安全な変換、拍子・形式の共通処理 |
| `src/validator.js` | 共通Schemaでの検証、参照先・重複・拍数・要確認のチェック |
| `src/parser.js` | 正式JSONから再生エンジン用データへの変換 |
| `src/editor.js` | 編集用の下書き、試聴、確認フロー、保存・書き出し |
| `src/navigation.js` | 有限の演奏順を生成。音声・DOMから独立 |
| `src/audio.js` | Web Audioの先読みスケジューラー、音色ファクトリー、カウントイン |
| `src/storage.js` | 曲一覧の保存。保存失敗時に既存データを維持 |
| `src/app.js` | UIイベントと状態の接続 |
| `src/score.js` | 音名・担当・音価による簡易楽譜の表示 |
| `sw.js` | アプリ資産のプリキャッシュ |

詳細は [JSON仕様](./JSON_FORMAT.md) を参照。オリジナルのサンプル曲は `samples/andean-dialogue.json`、移動記号を含む例は `samples/navigation-demo.json`。

## データを確認・修正する

曲を選んで「データ編集」を開き、小節を選びます。音符・休符の追加、削除、並べ替え、音高・音価・前後担当の変更ができます。「この小節を試聴」は未保存の値と現在のBPMを使います。前後の小節をつなぐ試聴、前だけ／後だけ／両方にも対応し、練習と同じ音声エンジンを使います。

「要確認のみ確認」から順に見直し、「確認済みにする」で次へ進みます。空eventsと担当未設定の音符は、修正するまで確認済みにできません。拍数の過不足は警告で、弱起などの例外は保存できます。曲進行は下の「曲進行」で修正し、演奏順プレビューで確認します。

「保存」でこの端末の曲を更新。「JSONを書き出す」「JSONをコピー」は現在の編集内容を取り出します。クリップボードを使えない環境では選択可能なJSON欄を表示します。練習に戻っても下書きは保持しますが、練習再生には保存済みデータを使います。曲切替・ページ離脱では未保存の変更を確認します。

空eventsの曲は未完成であることを大きく表示します。無音時間を勝手に休符へ変換せず、音符の推測も行いません。いただいたような構造だけのJSONも、音符を入力するための出発点として使えます。

## 正式JSON仕様

基準は [song.schema.json](./song.schema.json)。ChatGPTへ楽譜からJSONを作成してもらう場合、このファイルと [仕様・依頼文](./JSON_FORMAT.md) を渡してください。

必須のルートフィールドは `formatVersion:"1.0"`, `title`, `bpm`, `part:{id,name,instrument}`, `key`, `defaultTimeSignature:{numerator,denominator}`, `markers`, `navigation`, `measures`。1ファイル1パートで、楽器名は制限しません。

各小節は `number`, `timeSignature:null`（または変更拍子）, `events`, `needsReview`。音符は `type:"note",pitch:"G3",duration:0.5,role:"front",needsReview:false`、休符は `type:"rest",duration:0.5,needsReview:false`。durationは四分音符=1、roleはfront/back/both/unknownです。完全なJSON例とNavigationEventの全フィールドは仕様書に記載しています。

コード内の定義は `src/schema.js` に一元化し、インポート・保存で同じ定義を使います。`npm run schema` で配布Schemaを再生成し、テストで一致を確認します。JavaScriptのまま軽量に保ち、`src/types.d.ts` にSongData等の型も用意しました。

旧defaultTempo/parts/score/notes/player等は読み込み時に変換します。複数パートの旧JSONは全パートを別の曲一覧項目として保存し、元の保存済みライブラリは移行時にバックアップします。

## 楽器・楽譜がないときの試し方

1. 「デモを選ぶ」→「前と後を聴き分ける」で1〜4小節を両方聴きます。
2. 「自分が吹く：前」に切り替えます。簡易楽譜で「前」と書かれた音を口ずさむと、アプリの「後」と掛け合えます。
3. 「反復からCodaへ」では、演奏順が `1,2,3,1,2,4,5,6,7,5,6,9,10` になることを確認します。
4. 「55〜60小節をループ」では、60小節から55小節への戻りと「もう一度」を試します。「全小節」に広げると61小節から6/8に変わります。

デモを選ぶと曲を端末に保存し、範囲・テンポ・モードを準備します。自動では再生しません。同じデモの再選択で曲が増えることもありません。サンプルは `samples/range-demo.json` を含めすべてオフラインキャッシュに入ります。

## MVPの範囲と注意

- 単旋律、実音指定、単純なtriangle波の音色です。調による自動移調、和音、タイ、写真認識、楽譜画像表示、バックグラウンド再生は含みません。
- D.C./D.S.後は反復を省略し2番以降の括弧へ進む規則です。詳細と区間境界の扱いはJSON仕様に記載しています。
- テンポ・担当・メトロノームの変更は、すでにスケジュール済みの約100msの音を除き反映されます。発音中の音の長さは変更されません。
- 保存先はこの端末・ブラウザー・サイトの組み合わせごとです。ブラウザーデータ消去やサイト変更で曲を失うため、元のJSONを保管してください。
- オフラインキャッシュの更新時は `sw.js` の `CACHE` を変更してください。新しいWorkerは開いているアプリをすべて閉じた後に有効になり、新旧資産の混在を避けます。
- 実機のオーディオ出力・Bluetooth遅延は端末に依存します。公開後、Android Chromeで初回インストール、機内モードでの再起動、音量と音程を確認してください。

PNGアイコンとサンプルを再生成する場合: `node scripts/generate-assets.mjs`。
